# Assessment and Demo Guide

## Prerequisites

Use an isolated demo database or disposable test records. Obtain authorized demo accounts from the project maintainer. Do not use real production contracts or personal bidder information.

The demo accounts are:

- `admin@example.com` - ADMIN
- `approver@example.com` - APPROVER
- `submitter@example.com` - SUBMITTER

The passwords are generated by `backend/prisma/seed-demo-users.ts`; they are demo-only credentials. This guide does not repeat or publish them.

## 1. Login

1. Open `http://localhost:3000/login`.
2. Sign in with an authorized demo account.
3. Confirm the dashboard or assigned navigation is available for the account role.
4. Open `/api/auth/me` through the application if browser/network checks are required.

## 2. Create a draft

As SUBMITTER:

1. Open `/contracts/new`.
2. Enter the published form fields, department, category, sponsor, scope, rationale, and amount data.
3. Save the draft.
4. Open `/contracts` and confirm the draft is visible.

## 3. Edit a draft

1. Open the draft detail page.
2. Change a value and save.
3. Refresh the page and confirm the saved value persists.
4. Add bidder, quotation, cost-line, and evaluation data if the workflow requires them.

## 4. Attach documents

On a DRAFT or RETURNED contract owned by the submitter:

1. Open the contract attachments area.
2. Upload permitted PDF, Office, image, or text files according to the configured policy.
3. Confirm the attachment metadata appears.
4. View or download the attachment.

Upload is blocked if `DOCUMENT_*` variables or Google Drive configuration are unavailable. See [20-file-access-security.md](20-file-access-security.md).

## 5. Submit

As SUBMITTER:

1. Complete the required contract fields.
2. Submit the contract.
3. Confirm status changes to `PENDING_APPROVAL`.
4. Confirm the record no longer remains editable as a draft.

## 6. Approve

As an assigned APPROVER or ADMIN:

1. Open `/approvals`.
2. Select the pending contract.
3. Add an approval decision.
4. Confirm the approval step status and approval history update.

Only the assigned approver for a step can submit that step's decision.

## 7. Return or reject

As an assigned APPROVER:

1. Open an approval detail.
2. Choose Return or Reject.
3. Enter the required/commented reason according to the UI.
4. Confirm status becomes `RETURNED` or `REJECTED`.

For a returned contract, the submitter can resubmit after editing.

## 8. PDF

On an accessible contract:

1. Use the contract PDF action to generate or download the current PDF.
2. Verify contract values, bidders, cost lines, and approval history shown in the PDF.

Approved final-PDF actions generate or retrieve a stored PDF attachment. Storage requires Google Drive configuration.

## 9. Dashboard filtering

Open `/dashboard` and `/contracts`. Supported list behavior should be verified from the live UI. Dashboard counts are separated by status and scoped by role:

- ADMIN: all contracts
- APPROVER: contracts for which the approver has an approval step
- SUBMITTER: contracts created by that submitter

## Assessment checklist

- [ ] Login works for authorized submitter, approver, and admin accounts
- [ ] Draft save and edit persist
- [ ] Submission changes status to pending approval
- [ ] Assigned approver can approve
- [ ] Unauthorized approvers receive a 403 response
- [ ] Return and rejection update status
- [ ] Returned contract can be edited and resubmitted
- [ ] Attachment list/view/download works
- [ ] PDF opens and contains saved values
- [ ] Dashboard counts follow role visibility
- [ ] Unauthorized direct URLs return 401 or 403

## Remaining manual verification

External Google Drive access, PDF visual layout, responsive layouts, real mobile devices, and email notifications require explicit environment access and are not presumed by this guide. Azure frontend, backend, and database health are live-verified, but authenticated business workflows remain subject to available role accounts.
